# AI 介入体验整改路线图（M1–M4）

> 目标：把「AI 接入一次排障」的闭环磨顺，而不是增加功能数量。
> 当前状态：多连接定向 attach、独立 replay、活跃标签上报已完成；本文档覆盖剩余整改项。
> 优先级定义：**P0 = 直接影响 AI 介入可用性或安全**；P1 = 运维排障效率；P2 = 接入与合规体验。

---

## 一、本次问题与根因

现象：复制 SSH 渠道并关闭旧标签后，AI 再执行命令，界面看不到 `[AI 执行]` / `[AI 结果]`。

根因：

- `emit_terminal_text` 固定把 AI 回显写入主 Shell 的 replay，并且只广播 `terminal-data`。
- 复制渠道标签监听的是 `session-channel-output`，收不到主终端事件；旧主标签关闭后，AI 回显没有任何可见载体。
- AI 回显混在人工终端中，也无法直观回答「AI 现在附着在哪块屏幕」。

结论：AI 输出必须走**独立通道**，并有**独立只读标签**承载。

---

## 二、已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| AI 输出默认位置 | 只进入独立 AI 标签；设置中提供「同时在人工终端回显」开关，默认关闭 |
| AI 标签权限 | 人类只读：可查看、可选中复制，不能输入、不能粘贴、不能执行命令 |
| AI 标签生命周期 | attach 时创建；detach 后保留只读历史，可手动关闭 |
| AI 标签与活跃终端 | AI 标签不参与 `set_active_terminal` 上报，避免被当成用户正在看的连接 |
| 多连接绑定 | 继续使用已实现的固定 `connection_id + generation` 绑定，不自动跟随活跃标签 |

## 三、里程碑与交付范围

### M1 — AI 独立只读标签（P0，先交付）

> 状态：已完成并通过真机验收（2026-11-22）。后端独立 `ai_replay`、`ai-terminal-data`、AI 只读标签、双显开关、附着状态与审批单消耗修复均已完成；Kali 真机回归 5/5 通过（含主标签输出、复制渠道、关闭旧标签）。

| 编号 | 交付项 | 说明 |
| --- | --- | --- |
| M1-1 | AI 独立输出通道 | 新增 `ai_replay` 与 `ai-terminal-data` 事件；所有 AI 回显统一经 `emit_ai_text` 输出 |
| M1-2 | 独立只读 AI 标签 | 每个已 attach 会话固定一个「AI 只读」标签，带 AI 徽标；attach 时创建并仅首次自动激活 |
| M1-3 | 人类只读保护 | `Terminal` 增加 `readOnly`：禁用键入、粘贴与输入事件；保留选中复制 |
| M1-4 | 附着状态可视化 | 标签/状态栏显示 `connection_id`、主 Shell/复制渠道、模式、剩余时间、sudo 配额 |
| M1-5 | 双显开关 | 设置项「AI 输出同时在人工终端回显」，默认关闭 |
| M1-6 | 历史回放 | 新增 `read_ai_terminal(session_id, after_seq)`，AI 标签晚挂载可补齐历史 |
| M1-7 | 审批单消耗缺陷修复 | 先校验 writer 冲突与连接存在，再消费审批；失败不得把审批标记为已消费 |

**验收标准**

- 关闭、切换、重组任意人工标签后，AI 执行过程仍完整出现在 AI 标签中。
- AI 标签无法输入任何字符，粘贴与右键粘贴均不可用。
- 开启双显后，人工终端与 AI 标签同时可见；关闭后人工终端不再出现 AI 回显。
- detach 后 AI 标签保留历史，再次 attach 会续接新的执行记录。
- 「已有 AI writer 接入中」导致 attach 失败后，原审批仍可直接重试，无需重新批准。
- AI 标签显示期间，`session_read` 的活跃连接判断不受影响。

### M2 — 只读执行与任务级授权（P0）

> 状态：代码与自动化测试已完成，并随 1.0.0-2 发布（2026-11-22）；待 Kali 真机验收。
> 已完成：`mode=diag` 非独占只读执行与白名单（`ai_diag_allowlist`）、任务级授权（`task.goal` / `ttl_minutes`，任务内只读免审批、到期自动 detach 并写入 AI 标签提示）、sudo 错密返回 `SUDO_AUTH_FAILED` 与连续错密锁定、AI 标签显示任务与剩余时间。
> 自动化：`cargo test` 125 通过，`npm test` 147 通过，`npm run lint` 0 警告。

| 编号 | 交付项 | 说明 |
| --- | --- | --- |
| M2-1 | diag 只读模式 | 新增 `diag` 接入模式：非独占、多观察者、仅允许白名单只读命令（`ss`/`df`/`journalctl`/`systemctl status` 等） |
| M2-2 | 命令白名单与审计 | 白名单显式配置、命中记录、越界命令拒绝并提示 |
| M2-3 | 任务级授权 | attach 增加 task 目标：任务内只读免逐条审批；写、高危、root 仍单独确认；任务结束自动 detach |
| M2-4 | sudo 错密缺陷 | 修复错误密码返回 `TIMEOUT` 而非 `SUDO_AUTH_FAILED`、连续错密锁定不触发的问题；修复前 UI 明示 |
| M2-5 | AI 标签状态联动 | diag/任务模式在 AI 标签状态栏显示当前任务、剩余范围与自动 detach 时间 |

**验收标准**

- diag 模式下 `session_exec` 仅能执行白名单命令，写命令返回明确错误。
- diag 观察者不阻塞 writer，也不被 writer 阻塞。
- 任务内连续只读命令只审批一次；写/高危/root 仍逐条确认。
- 错误 sudo 密码返回 `SUDO_AUTH_FAILED`，连续错密触发锁定。
- 任务结束后 token 自动失效，AI 标签标注「任务已结束」。

### M3 — 运维效率（P1）

| 编号 | 交付项 | 说明 |
| --- | --- | --- |
| M3-1 | 诊断快照 | `session_monitor` 输出 bps/pps、TCP 重传率、UDP RcvbufErrors、TIME_WAIT/SYN_RECV、Top 连接 |
| M3-2 | 敏感内容脱敏 | 对 `password:`、`token`、`BEGIN PRIVATE KEY` 等默认打码；支持临时放开并留审计 |
| M3-3 | 多行脚本 | `session_exec` 支持一次提交多行脚本，保持现有独立 exec 通道隔离 |
| M3-4 | Shell Integration | 连接时可注入 bash/zsh precmd 钩子，上报 `user@cwd` 与上条命令退出码，补齐 `prompt_user` |
| M3-5 | 多会话只读批量 | 支持同一 AI 客户端并发只读 attach 多台主机；聚合与对比由 AI 侧完成 |

**验收标准**

- 诊断快照一次调用可替代多次手工采样，数值与手工命令一致。
- 脱敏规则命中后聊天与日志均不出现明文秘密；放开操作有审计记录。
- 多行脚本作为一次执行返回统一退出码与输出。
- Shell Integration 可用时 `prompt_user` 非空并带来源与观测时间；不可用时保持 `null`。
- 多会话只读 attach 互不干扰，任一连接关闭不影响其他连接。

### M4 — 接入与合规（P2）

| 编号 | 交付项 | 说明 |
| --- | --- | --- |
| M4-1 | MCP 配置一键生成 | 设置页生成 Trae / Claude / Cursor 的 MCP JSON，自动带 `Bearer` 前缀 |
| M4-2 | 凭证轮换引导 | 轮换后提示需要更新的客户端；401 返回可读失效原因 |
| M4-3 | AI 活动审计面板 | 命令、结果、耗时、审批人、sudo 使用、attach/detach 时间线，支持导出 Markdown |
| M4-4 | 默认高危黑名单 | 内置 `rm -rf /`、`mkfs`、`dd of=/dev/*`、`iptables -F`、写 `authorized_keys`、`curl ... | sh` 等规则 |
| M4-5 | 稳定性 | 提权运行场景、单实例检测、异常退出清理，避免僵尸进程与 AppHang |

**验收标准**

- 复制出的 MCP 配置可直接粘贴使用，无需手工补 `Bearer`。
- 凭证轮换后旧凭证请求返回明确原因与更新指引。
- 审计时间线可完整还原一次 AI 排障过程并导出。
- 默认黑名单开箱拦截高危命令，且可审计。
- 提权启动、异常退出后可再次正常启动，不残留进程。

## 四、优先级与依赖关系

| 顺序 | 里程碑 | 优先级 | 依赖 |
| --- | --- | --- | --- |
| 1 | M1 | P0 | 无，直接基于已完成的多连接绑定 |
| 2 | M2 | P0 | M1 的 AI 通道与标签状态栏 |
| 3 | M3 | P1 | M2 的白名单与任务模型（脱敏、快照可独立先行） |

**原则**：M1 未验收前不启动 M2 的界面部分；安全类缺陷（M1-7、M2-4）不因功能排期而延后。

## 五、外部建议评估结论

| 建议 | 结论 | 归属 |
| --- | --- | --- |
| 任务级授权替代逐次审批 | 采纳 | M2-3 |
| 前置校验失败不消耗审批单 | 采纳（缺陷） | M1-7 |
| AI 附着位置可视化 | 采纳 | M1-4 |
| 只读 exec / diag 模式 | 采纳 | M2-1、M2-2 |
| sudo 错密缺陷 | 采纳（安全） | M2-4 |
| 跨主机批量诊断 | 部分采纳：先做并发只读 attach，聚合交给 AI | M3-5 |
| 诊断快照升级 | 采纳 | M3-1 |
| Shell Integration | 采纳，需评估 shell 兼容与注入安全 | M3-4 |
| 多行脚本 / 持久 cwd | 部分采纳：先做多行脚本；持久 cwd 另行设计会话级 shell | M3-3 |
| 敏感内容脱敏 | 采纳 | M3-2 |
| MCP 配置一键生成 | 采纳 | M4-1 |
| 凭证轮换引导 | 采纳 | M4-2 |
| AI 活动审计面板 | 采纳，先支持 Markdown 导出 | M4-3 |
| 默认高危黑名单 | 采纳 | M4-4 |
| 稳定性（提权、单实例、僵尸进程） | 采纳 | M4-5 |

### 明确不做 / 暂不做

- **不自动跟随活跃标签**：会让同一 token 的 replay 跨连接，制造更隐蔽的错配。
- **不把 `prompt_user` 用正则或 `id -u` 猜测**：只在可靠 shell integration 上报时填写。
- **不为 diag 模式开放任意命令**：白名单之外一律拒绝，避免"只读模式"变成绕过审批的入口。
- **不在 M1 引入任务编排层**：批量诊断先停留在"多会话只读 attach"，避免过早复杂化。

## 六、风险与约束

| 风险 | 应对 |
| --- | --- |
| AI 标签抢占焦点 | 仅首次 attach 自动激活，之后不抢焦点 |
| AI 输出内存增长 | `ai_replay` 使用与终端一致的容量上限并滚动淘汰 |
| 双显开关导致回显重复 | 双显只影响人工终端，AI 标签始终只保留一份 |
| 只读标签被误认为可输入 | 标签常驻「AI 只读」徽标，悬停提示不可输入 |
| 任务级授权被滥用 | 任务范围、结束时间、命令类别全部写入审批与审计 |
| 白名单误放行 | 白名单需显式配置并有变更记录，默认最小集合 |

## 七、确认项

以下决策已确认，作为实施依据：

1. 本次先交付 M1，再按 M2 → M3 → M4 推进。
2. AI 输出默认只进 AI 标签；双显开关默认关闭。
3. AI 标签在 detach 后保留只读历史。
4. 安全类缺陷（审批单消耗、sudo 错密）优先于效率类功能。
