SFTP 独立窗口模块拆分

Chena-Shell v1.2 — 产品需求文档 · 2026-11-18

1. 背景与目标

观察到的问题

Chena-Shell v1.1 把 SFTP 内嵌在底部工具栏（Terminal / SFTP / 快速命令 / 日志 / 资源监控 五个 tab）。实际使用中出现：

  • 空间局促：底部面板高度有限，左右双面板文件列表只能各显示 3~4 行，浏览大量文件时必须频繁滚动
  • 上下文切换：用户在终端跑命令同时需要传文件，切 tab 就打断终端视线
  • 无法并行：不能一边在终端里操作，一边在 SFTP 里拖拽大文件
  • 不符合用户心智模型：用户熟悉的 WinSCP / Bitvise SSH Client 都是 SFTP 独立窗口，和终端并列

产品决策

将 SFTP 从底部工具栏拆出，改为独立弹出窗口，在左侧 Sidebar 会话卡片上增加 SFTP 入口按钮。底部工具栏恢复为固定高度，只保留 Terminal 相关 tab。

可观测的结果

  • 用户从 Sidebar 点 SFTP 按钮 → 弹出独立 SFTP 窗口（可拖拽、最大化）
  • SFTP 窗口完整采用 WinSCP 风格左右双面板 + 顶部工具栏 + 底部传输队列
  • SFTP 窗口和主终端窗口可以并行：主窗口终端继续跑命令，SFTP 窗口独立操作

2. 范围

P0 — 完成核心旅程所需的全部功能

模块入口完成条件
Sidebar SFTP 入口会话卡片第二行新增 SFTP 按钮点击后弹出独立窗口
SFTP 主窗口框架Tauri 新 Webview 窗口窗口尺寸 1000×640，可拖拽/最大化/最小化
左右双面板（WinSCP 风格）本地面板 + 远方面板都有地址栏、目录返回、文件列表、右键菜单
文件操作右键菜单 / 拖拽上传、下载、重命名、删除、改权限、新建目录
传输队列底部可折叠面板显示进行中/等待中/完成/失败，支持取消
底部工具栏瘦身原 BottomPanel移除 SFTP tab，恢复固定高度（不再可拖动）

P1 — 相关但非必要

  • SFTP 窗口记住上次位置和尺寸（localStorage）
  • 本地文件路径历史（最近访问过的目录）
  • 传输队列持久化（关闭窗口后下次打开恢复未完成任务）

明确不做

  • 不再实现 SCP 协议（只用 SFTP subsystem）
  • 不再实现同步 Mirror（WinSCP 的 Synchronize）
  • 不再实现远程文件搜索
  • 底部工具栏的 splitter 拖拽功能整体移除

4. 功能需求

FR-01 · Sidebar SFTP 入口

Purpose

用户从会话卡片直接触发 SFTP 窗口，不需要先打开终端或底部工具栏。

Layout（Sidebar 会话卡片第二行）

┌─────────────────────────────────────────┐ │ ● my-server │ ← 第一行：绿点 + 会话名 │ ubuntu@192.168.1.100:22 │ │ [SFTP] [断开] [🗑] │ ← 第二行按钮组（新增 SFTP） └─────────────────────────────────────────┘

Trigger 处理规则

场景行为
Session 未连接，点 SFTP先自动发起连接 → 连接成功 → 打开 SFTP 窗口
Session 已连接，点 SFTP直接打开/激活 SFTP 窗口
SFTP 窗口已打开（被遮挡）窗口 focus + 提到最前
SFTP 窗口已最小化还原窗口

按钮状态

条件按钮样式点击行为
Session.connected=true实心主题色打开/激活 SFTP 窗口
Session.connected=false灰色，hover 提示"需先连接"先连接，成功后打开 SFTP
SFTP 已打开 + 有活跃传输按钮右上角显示数字角标（运行中 job 数）激活窗口

FR-02 · SFTP 独立窗口框架

Purpose

SFTP 作为独立 Tauri Webview 窗口，拥有自己的生命周期、标题栏和关闭/最小化/最大化。

窗口规格

属性值说明
窗口类名"sftp-{session_id}"每个 Session 独立窗口实例
默认尺寸1000 × 640首次打开
最小尺寸720 × 480防止面板挤到不可用
默认位置主窗口偏右 40px避免完全遮挡主窗口
窗口标题"SFTP — {session.name} ({session.username}@{host})"动态更新
数量限制每个 Session 最多 1 个 SFTP 窗口点重复打开按钮 → focus 已有窗口

关闭窗口行为

场景行为
无活跃传输，用户点 ✕直接关闭窗口，传输队列丢失（P0 不持久化）
有活跃传输（进行中），用户点 ✕弹出确认对话框："有 N 个文件正在传输，确定关闭？关闭后传输将被取消"
有等待中传输，用户点 ✕同上（警告弱一档："有 N 个等待中的传输任务"）
最小化窗口缩到任务栏，传输继续在后台运行

Purpose

完整抄 WinSCP / Bitvise SSH Client 经典布局。本地和远端文件系统并列显示，通过拖拽或右键触发传输。

完整窗口布局

单面板详细结构

区域元素行为
标题"本地 🖥" / "远端 ☁"远端状态灯：绿=已连接 / 红=未连接
路径栏可编辑输入框 + 📁 选择器按钮回车 = 跳转；📁 = 系统对话框（仅本地）
目录返回↑ 按钮返回父目录（本地 `..` / 远端 `cd ..`）
文件列表图标 + 名称 + 大小 + 类型单击选中；双击进入目录；右键弹出上下文菜单
选中行整行高亮（主题色容器色）本地和远端各自独立维护选中状态
空状态"空目录" + 灰文字允许右键 → 新建目录
错误状态红框 + 错误信息（如 Permission denied）提供"重试"按钮

拖拽传输规则

拖拽方向触发的动作
本地 → 远方面板自动创建上传任务（多文件 = 多 job 并行）
远端 → 本地面板自动创建下载任务
本地 → 本地（同面板内拖拽）不触发（P0 不做本地移动）
远端 → 远端（同面板内拖拽）不触发（P0 不做远端移动）
拖拽到目标面板空白处同上（整个面板都是有效 drop zone）
拖拽文件不存在时松手忽略，不创建任务

字段示例说明
方向箭头⏬ 或 ⬆下载/上传
文件名main.py源文件名

队列操作

操作适用状态行为

5. 共享规则与异常

Session 连接状态联动

  • SFTP 窗口的远方面板列表刷新依赖 Session.connected=true
  • 如果 Session 断连，SFTP 窗口自动：① 远方面板清空 ② 传输队列中所有进行中 job 失败 ③ 标题栏显示 "(已断开)"
  • Session 重连后，SFTP 窗口不会自动恢复传输 — 需要用户手动重新发起（避免半拉子状态）

错误处理

错误场景处理方式
Permission denied（403）传输 job 标记 ✕ 失败，路径栏显示红色提示；已下载/上传的部分文件清理（P1）
文件太大（>100MB）警告对话框："大文件 {n}MB，上传可能很慢"
网络中断SSH 层自动重连（现有 russh 实现）；重连恢复后传输 job 暂停
SFTP subsystem 不可用远方面板显示："服务器未启动 SFTP subsystem (sftp-server)"，建议用 SCP 替代
删除目录非空二次确认 "确定删除 {dir} 及其 {n} 个文件？此操作不可恢复"

并发控制 [Assumption, TBD]

  • P0：同一 Session 最多 1 个上传 + 1 个下载 并发，其他进入等待队列
  • P1：允许用户在 Settings 里调整并发数（1~4）
