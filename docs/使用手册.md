# Chena-Shell 使用手册

> 适用版本：V1.0.0.12（Windows x64 绿色版）
> 适用对象：日常使用 SSH 终端、SFTP 传文件、需要让 AI 协助排查服务器的用户
> 配套文档：[AI 使用说明](AI-使用说明.md)，以及绿色版根目录的 `SKILL.md`

---

## 1. 安装与启动

### 1.1 运行前提

- Windows x64。
- 需要 Microsoft Edge WebView2 Runtime。Windows 10/11 通常已自带；如启动失败或白屏，请从微软官方页面安装 WebView2。
- 绿色版不会自动安装 WebView2。

### 1.2 启动方式

1. 解压 `Chena-Shell_V1.0.0.12_portable.zip`。
2. 双击 `Chena-Shell_V1.0.0.12.exe`。
3. 无需安装。应用配置、日志和编辑缓存保存在 `%APPDATA%\chena-shell`，删除程序目录不会删除这些数据。

压缩包根目录包含 `Chena-Shell_V1.0.0.12.exe`、`使用手册.md`、`AI-使用说明.md`、`SKILL.md`、`更新记录.md` 和 `PORTABLE-README.txt`。需要让其他 agent 接入时，应解压并保留完整目录，把 `AI-使用说明.md` 与 `SKILL.md` 一起交给 agent，不要只复制 EXE。

绿色版启动时不会弹出黑色控制台窗口，这是正常现象。

### 1.3 首次启动

首次启动会自动创建配置目录，无需手动准备。

主窗口分为三块：

| 区域 | 用途 |
| --- | --- |
| 左侧会话列表 | 新建、选择、连接会话；右键菜单提供常用操作 |

顶部工具栏提供命令面板（`Ctrl+K`）入口、设置、切换主题等按钮。

## 3. 会话管理

### 3.1 新建会话

1. 点击左侧「新建会话」或按 `Ctrl+K` 搜索「新建会话」。
2. 填写名称、主机、端口、用户名。
3. 选择认证方式：
   - 密码；
   - 私钥文件（选择本地私钥路径，可填口令）；
   - 直接粘贴私钥内容（内容保存到 Windows 凭据管理器，不写入明文配置）。
4. 可选配置：分组、ProxyJump 多跳、Keepalive、连接超时、自动连接、终端日志、端口转发、AI 安全策略。
5. 保存。

### 3.2 连接与断开

- **双击会话**：未连接时直接连接；已连接时不会重复连接。
- 右键菜单「连接 SSH / 断开连接」。
- 连接成功后，终端标签自动创建并**自动激活**，左侧选择其他会话时也会新增并激活对应标签。
- 首次连接某台主机时，需要核对并确认主机密钥指纹（TOFU）。主机密钥发生变化时会单独提示，必须比对旧、新指纹后再决定，不要盲目放行。

### 3.3 右键菜单

左侧会话列表与顶部终端标签页使用同一套右键菜单；在标签上右键同样会作用于该标签对应的会话。

| 菜单项 | 说明 |
| --- | --- |
| 打开 Chena-Sftp 窗口 | 打开该会话的双栏文件传输窗口；未连接时会先建立连接 |
| 复制 SSH 渠道 | 在**同一会话、同一 SSH 连接**上再开一个独立 shell 通道，新标签自动激活 |
| 连接 SSH / 断开连接 | 建立或关闭连接 |
| 编辑会话 | 修改配置 |
| 复制主机信息 | 复制 `用户名@主机:端口` |
| 删除会话 | 删除配置（会二次确认） |
| 关闭标签 | 仅标签页菜单提供；关闭当前标签，最后一个入口时按连接状态提示是否断开 |

### 3.4 标签与分屏

- 同一会话存在多个标签（如多次「复制 SSH 渠道」）时，标签按顺序显示 `[1]`、`[2]` 序号，避免同名无法区分。
- 顶部「拆分当前终端」把当前标签拆成左右两个窗格，每个窗格可独立操作。
- 关闭标签时，如会话仍在连接，会提示确认后再断开。
- 标签右键菜单与左侧会话列表一致，另提供「关闭标签」。

## 4. 终端操作

| 操作 | 方式 |
| --- | --- |
| 复制 | 选中文本后 `Ctrl+C`，或 `Ctrl+Shift+C` |
| 粘贴 | `Ctrl+V` / `Ctrl+Shift+V`；开启「多行粘贴前确认」时会先提示行数 |
| 无选区时 `Ctrl+C` | 照常发送中断信号 `^C` |
| 搜索 | `Ctrl+F` |
| 放大 / 缩小字号 | `Ctrl+加号` / `Ctrl+减号`，或 `Ctrl+鼠标滚轮` |
| 恢复默认字号 | `Ctrl+0` |
| 打开链接 | 按住 `Ctrl` 点击 HTTP(S) 链接 |

终端内右键提供「复制」「粘贴」「粘贴所选」。

鼠标点击定位：

- 普通 Bash 等 shell 中，可直接用未按组合键的左键点击当前命令行（含同一逻辑换行）的目标位置来移动光标；点击历史输出、其他命令行、已有选区或进行拖拽选择时不会触发定位。
- Vim 等支持终端鼠标协议的远程程序启用鼠标模式后，点击、拖动和滚轮事件会发送给远端，由程序自行移动光标；Vim 中先执行 `:set mouse=a`。
- 同时转发现代 SGR 文本鼠标事件和旧式 xterm 二进制鼠标事件，高位坐标不会被 UTF-8 转码破坏；默认终端与复制 SSH 渠道均可使用。

## 6. Chena-Sftp 文件传输

### 6.1 打开

在会话右键菜单选择「打开 Chena-Sftp 窗口」，或在命令面板搜索「打开当前会话 SFTP」。未连接时会先建立 SSH 连接。

### 6.2 界面

- 左栏本地、右栏远端，各自有后退、前进、上一级、刷新、路径输入和面包屑。
- 顶部工具栏：返回主窗口、刷新本地、刷新远端、删除远端选中项、显示隐藏文件、同步浏览。
- 支持把文件/文件夹从一侧拖到另一侧上传或下载。
- 远端文件右键菜单：刷新、编辑、下载（文件夹为「下载整个文件夹」）、删除、复制完整路径、查看详情、修改权限（chmod）。
- 本地文件右键菜单：刷新、上传到远端（文件夹为「上传整个文件夹」）、在资源管理器中打开、复制完整路径、属性。

### 6.3 隐藏文件规则

「显示隐藏文件」在两侧的判断依据不同：

- **本地**：按 Windows 文件属性判断（带「隐藏」或「系统」属性的条目视为隐藏），不再用 `.` 前缀判断。
- **远端**：按 Linux/Unix 惯例，以 `.` 开头的文件或目录视为隐藏。

目录中有隐藏项但未勾选时，列表下方会提示隐藏了多少项。

### 6.4 传输队列

- 窗口下方「传输队列」显示当前与历史任务。
- **新任务排在最上面**（倒序），方便查看最近进度。
- 运行中可暂停、取消；已暂停可恢复；失败可重试。
- 传输使用 `.part` 临时文件，完成后改名替换，减少半截文件；支持断点续传。
- 队列高度可拖动调整。

## 7. 远端文件编辑

### 7.1 编辑方式

进入「设置 → 通用 → 远端编辑」，可选择「编辑方式」：

- **内置编辑器（默认）**：在独立窗口中用 Monaco 编辑，支持 markdown / bash / python / yaml / json 高亮与诊断，`Ctrl+S` 直接保存到远端。
- **外部编辑器**：下载到本地缓存后调用你指定的外部程序（如 `code`、`notepad++`），关闭后回传。

### 7.2 内置编辑器使用流程

1. 在 SFTP 远端栏右键目标文件，选择「编辑」。
2. 弹出独立编辑器窗口，加载远端内容。
3. 修改后点「保存」或按 `Ctrl+S` 回传远端（先写 `.part` 再原子替换）。
4. 关闭窗口时若有未保存修改，会弹出确认：保存并关闭 / 放弃修改 / 取消。
5. 编辑期间若远端文件被他人改动，保存时提示「远端冲突」，可选择「覆盖远端」或取消。

### 7.3 内置编辑器功能

- 支持 markdown、bash、python、yaml、json 五种语言的语法高亮；json / yaml 带官方 worker 校验，markdown 仅高亮。
- **诊断**：python 用 tree-sitter 检测语法错误；shell 用 pureshellcheck（经 Pyodide 本地运行，见第 14 节许可声明）。首次打开 shell 文件会加载约 13 MiB 本地运行时，冷启动约 1–3 秒，之后毫秒级刷新；覆盖 71 项常见检查，完全离线不联网。可在设置中关闭。
- 工具栏：保存、只读/可编辑、自动折行、查找替换（`Ctrl+F`）、字号缩放（`A−` / `A+`）、关闭。
- 状态栏：当前语言、光标行列、字节数、诊断数、远端完整路径。
- 主题跟随全局设置（暗色 / 亮色）。

### 7.4 限制与冲突

- 内置编辑器支持 **20 MiB 以内**的文件；外部编辑器仍为 5 MiB。超出会提示并拒绝打开。
- 拒绝包含 NUL 字节或非 UTF-8 编码的文件，避免损坏二进制内容。
- 同一次编辑的原始版本会保留备份：`%APPDATA%\chena-shell\edit\<edit_id>\<文件名>.original`。
- 关闭 SFTP 窗口时若仍有进行中的传输任务，会先确认。

### 7.5 外部编辑器

选择「外部编辑器」后，可填写外部程序路径：默认 `notepad`（系统记事本），可填 `code`、`notepad++` 等，留空使用系统默认关联程序。修改并关闭外部程序后自动比较内容并回传。

## 10. 让 AI 接入

1. 「设置 → MCP服务」确认：
   - 已勾选「启用 MCP 服务」；
   - 监听地址为 `127.0.0.1`（默认，仅本机可访问）；
   - 端口默认 `8767`。
2. 点「重新生成凭证」，复制完整凭证。
3. 在 AI 客户端中配置 MCP：
   - HTTP：`http://127.0.0.1:8767/mcp`，请求头 `Authorization: Bearer <凭证>`；
   - stdio：运行 `Chena-Shell_V1.0.0.12.exe --mcp-stdio`，设置环境变量 `CHENA_MCP_TOKEN`（非默认端口时再设置 `CHENA_MCP_URL`）。
4. AI 请求接入时，界面会弹出审批，由你决定是否允许。

让其他 agent 接入时，把绿色版根目录的 `AI-使用说明.md` 和 `SKILL.md` 一起交给它。agent 应先引导你完成上述 MCP 开关、凭证生成和客户端配置，再尝试调用工具。MCP 访问凭证与接入后返回的 `attach_token` 不是同一种凭证，不能混用。为减少泄露风险，优先由你本人把凭证直接粘贴到 MCP 客户端配置中，不必发到聊天里；重新生成凭证后旧值立即失效，需要同步更新客户端。

**AI 接入令牌的生命周期**

- `attach_token` 只在与签发它的那次 MCP 连接内有效，不能跨客户端连接使用。
- AI 客户端重连 MCP 或重启后，旧 token 全部失效，必须重新 `session_attach`；用旧 token 执行命令会返回「token 与当前客户端或会话不匹配」。
- 旧 token 也不能在另一个 MCP 连接里 detach。若客户端已经断开、无法主动收尾，该接入会按「接入令牌有效期」（默认 30 分钟）自然过期；你也可以在 Chena-Shell 界面强制断开。
- 需要立即回收时，优先在界面断开，或让原 MCP 连接先 detach 再关闭。

AI 实际开始执行命令后，对应会话的主虚拟终端会默认显示：

- `[AI 执行]`：完整命令文本；
- `[AI 结果]`：命令、stdout 和 stderr；
- `[AI 状态]`：成功、失败或超时，以及退出码和耗时。

被阻断或还在等待审批的命令不会显示为已执行。回显仅用于本机查看和内存回放，不会注入你正在操作的远端 shell，不会自动切换标签，也不会写入复制 SSH 渠道的独立终端或交互 shell 日志。

**AI 接入哪个终端**

同一会话存在多个终端（主 Shell + 多个「复制 SSH 渠道」）时，AI 不会再默认读取主 Shell：

- 接入审批会显示目标 `connection_id`、登录用户和连接时间，你能看到 AI 要接入哪个终端；
- 未指定连接时，AI 会绑定你当前正在看的标签；若此时无法判断活跃标签，接入直接报错让 AI 明确选择，不会静默读错终端；
- AI 读取的回放固定属于接入时绑定的连接；你切换标签后，严格模式会明确提示「活跃连接已变化」，AI 必须重新申请接入，不能沿用旧回放位置；
- 关闭复制渠道或重新连接后，旧的 AI 接入自动失效，需要重新申请。

切换标签、分屏、关闭窗格等操作都会实时上报给后端，无需手动刷新。

**AI 只读标签**

AI 接入后，标签栏会新增一个带「只读」徽标的 AI 标签：

> 「只读」指的是**人类对这个标签只读**，不是 AI 不能执行。AI 仍按接入模式（write / diag）执行命令，你只能查看它的执行过程，不能在这个标签里输入、粘贴或执行任何命令。

- 该标签集中显示 `[AI 执行]`、`[AI 结果]` 和 AI 状态，不再混进人工终端标签；
- 你关闭、切换或重组任何人工标签，都不影响 AI 执行过程的显示；
- 标签内不能输入、不能粘贴、不能执行命令，只能查看和选中复制（选中后按 `Ctrl+C` 或 `Ctrl+Shift+C`）；
- 标签里的命令、输出和状态会同时写入 AI 回显日志，应用重启后仍可在底部「日志 → AI 日志」中查看；该日志始终记录，不受会话终端日志开关影响；
- 标签栏顶部显示 AI 附着的 `connection_id`、模式、剩余时间和 sudo 授权状态；
- AI 断开后标签保留历史记录，可手动关闭；再次接入会重新出现并续接新记录；
- 想要让 AI 回显同时出现在人工终端，可在「设置 → MCP 服务 → AI 输出」中开启「AI 输出同时在人工终端回显」，默认关闭。

**只读诊断（diag）与任务级授权**

- AI 可以选择 `mode=diag` 接入：不独占终端，多个观察者可同时存在；只能执行「设置 → AI安全 → 只读诊断与任务级授权」白名单内的只读命令，且不允许管道、重定向、命令串联和 root。
- 白名单匹配规则：普通条目按完整命令或参数边界匹配（`ss` 放行 `ss -s`，不放行 `sss`）；以 `/` 结尾的条目按目录前缀匹配（`cat /proc/` 放行 `cat /proc/net/dev`）。
- 命令中的绝对路径必须落在白名单声明的文件或目录内；`ls`、`stat`、`du`、`df`、`wc`、`readlink`、`lsof` 等只输出元数据的命令可以带普通绝对路径，但 `/root`、`/etc/shadow`、`/etc/sudoers`、`.ssh` 与私钥文件始终拒绝。
- `..` 路径穿越、通配符（`*`、`[`、含 `/` 的 `?`）、`$` 与 `~` 展开，以及 `tail -f`、`journalctl --vacuum-*`、`crontab -r`、`curl -X/-D/-c`、`dig -f`、`sar -o`、`ss -K`、`dmesg -C` 等危险参数一律拒绝。
- 会话以 `root` 登录时，只读诊断只放行内置只读条目；自定义条目需要改用 `mode=write` 并逐条审批。
- AI 以 `mode=write` 接入时可以声明任务目标（`task`）。任务有效期内，白名单只读命令免逐条审批；写操作、高危命令和 root 仍需单独确认。
- 任务默认不超过 120 分钟（设置中可调 1–1440 分钟），到期后自动 detach，并在 AI 只读标签中写入「任务已结束」提示。
- AI 只读标签状态栏会显示当前任务目标和任务剩余时间。

**审批倒计时**

审批弹窗默认 30 秒后自动拒绝。为了让你有足够时间看完申请内容，当鼠标移入审批窗口、或在窗口内点击、或激活 Chena-Shell 窗口时，倒计时会暂停并显示「倒计时已暂停」；鼠标移出窗口（或离开应用）后继续。暂停时长会补回到到期时间，不会因为你在阅读而误判超时。

**让 AI 以 root 执行（sudo，默认关闭）**

1. 打开「设置 → AI安全」，开启「允许 AI 以 root 执行」。
2. 可调整：sudo 密码来源（会话密码优先 / 仅手动输入 / 仅免密）、密码缓存（不缓存 / 本次接入 / 本次应用运行）、root 命令逐条确认、sudo 黑名单、sudo 确认清单、单次接入次数上限、密码错误锁定。
3. AI 接入时若申请 root 权限，接入审批会明确标注「执行身份：root」；每条 root 命令还会单独弹窗，显示命令原文、触发规则和影响提示，你可「批准一次」或拒绝。
4. 服务器需要密码时，会弹出「需要 sudo 密码」窗口，由你输入；密码只保存在本机内存，不会交给 AI，也不会写入命令行、日志或回放。
5. root 命令的执行回显为 `[AI 执行 root]` / `[AI 结果 root]` / `[AI 状态 root]`；被拒绝、被阻断、等待确认的命令不会显示为已执行。
6. 单次接入的 root 执行次数有上限（默认 50 次），超出后需断开并重新接入。
7. 密码错误时返回 `SUDO_AUTH_FAILED` 并计入失败次数；连续输错达到「密码错误锁定次数」（默认 3 次）后锁定「sudo 锁定时长」（默认 300 秒），锁定期间拒绝新的 root 执行。

详细的工具清单、调用流程和排障，见 [AI 使用说明](AI-使用说明.md)。

**AI 使用规范**

- 获得终端授权后，AI 应确认你本次的所有需求已经全部完成，再主动断开与 shell 的会话。
- 不要在单个问题刚验证完就提前断开；否则后续还要继续排查时必须重新授权，容易出现“问题没解决、却要一直授权”的情况。
- 需要结束或暂时不用 AI 时，可以让 AI 先汇总已完成的检查项和未完成事项，再执行断开。

详细的工具清单、调用流程和排障，见 [AI 使用说明](AI-使用说明.md)。

## 12. 常见问题

**启动白屏或打不开**
先安装/修复 Microsoft Edge WebView2 Runtime，再重试。

**连接失败**
检查主机、端口、用户名、认证方式；确认网络可达。使用 ProxyJump 时，确认每一跳都能连接。

**提示主机密钥变化**
说明服务端密钥与记录不一致。先核对新旧指纹来源，确认是合法变更再替换；无法确认时不要继续。

**本地看不到隐藏文件**
先勾选「显示隐藏文件」。本地是按 Windows 属性判断的，`.gitignore` 这类没有隐藏属性的文件默认会显示。

**远端编辑没有弹出编辑器**
确认「设置 → 通用 → 远端编辑使用的编辑器」填写正确；留空时使用系统默认关联程序。文件超过 5 MiB 会被拒绝。

**编辑后没有回传**
确认关闭的是编辑器窗口本身（不是最小化）；如果点过「取消」，则不会回传。可查看顶部通知状态。

**远端冲突如何处理**
说明编辑期间远端文件被改动。确认要保留本地版本时点「确认覆盖」；否则取消，本地原始备份仍在 `edit` 目录。

**取消生成凭证后为什么没有新凭证**
这是预期行为。只有点确认才会生成；取消不会产生新凭证。

**日志页显示未开启**
到「设置 → 日志存储」确认「默认记录终端日志」已开启，然后对已连接会话重连生效。

## 13. 已知边界

- 当前交付仅在 Windows x64 完成验证。
- 「复制 SSH 渠道」已实现同一连接上创建独立 shell 通道，并完成菜单、渠道对象与后端握手验证；但本机测试服务**未完成两个渠道真实双向字节流回显的复验**。在关键生产环境使用前，请先在目标服务器上人工确认两个渠道的输入输出互不干扰。
- 监控采集对 Linux、BusyBox、Windows、macOS/BSD 均有解析实现，但不同平台的实际验证范围不同。
- 主机监控与 AI 活动的部分专项验证使用模拟事件或测试 harness，不等同于真实服务器全场景验收。
