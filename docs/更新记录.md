# Chena-Shell 更新记录

> 记录面向用户的版本变更。详细设计与验收边界见 `项目说明文档.md` 与 `docs/AI-介入体验-整改路线图.md`。

## V1.0.0.11（2026-11-25）

### 变更

- **统一项目标识**：源码目录、文档、脚本与示例中的历史项目名已全部替换为 Chena-Shell，产品只保留一个名称。
- **移除旧数据目录迁移**：启动时不再扫描或搬迁早期数据目录，`%APPDATA%\chena-shell` 是唯一数据目录。
- **移除主题旧键兼容**：主题偏好只读取当前存储键，旧键不再生效。
- **构建脚本清理**：删除旧进程名与旧 DLL 残留检查，发布流程只针对当前产物。
- **文档隐私清理**：示例中的真实公网地址、本机 Windows 用户名和绝对路径已替换为占位值或相对链接。

### 升级注意

- 若此前使用过其他数据目录，需要在升级前手动复制到 `%APPDATA%\chena-shell`；本版本不会自动迁移。
- 主题偏好如出现回落，重新选择一次即可。

## V1.0.0.10（2026-11-23）

### 安全

- **关闭正式版开发者工具**：移除 release 构建的 `devtools` 特性、`toggle_devtools` 命令和 F12 / `Ctrl+Shift+I` 快捷键，正式版不能再打开 WebView 开发者工具，减少现场被调试和篡改的入口。
- **移除未使用的插件**：删除 `tauri-plugin-shell`、`tauri-plugin-dialog` 及对应的 `shell:default`、`dialog:default` 权限，以及 `plugins.shell.open` 配置。当前前端和后端都没有调用这两个插件，删除后不改变现有功能。
- **关闭全局 Tauri 注入**：`withGlobalTauri` 改为 `false`，页面不再暴露 `window.__TAURI__`；前端继续使用 ES 模块导入，功能不受影响。

### 说明

- 以上改动只缩小攻击面，不会消除沙箱报告中由 WebView2/Chromium 运行时产生的行为标签。
- 调试构建仍保留开发者工具；正式绿色版不再提供 F12 调试入口。

## V1.0.0.9（2026-11-23）

### 改进

- **AI 回显日志**：AI 只读标签中的 `[AI 执行]`、标准输出、错误输出和 `[AI 状态]` 现在会写入磁盘，应用重启后仍可追溯；此前这些内容只保存在内存回放中，关闭应用即丢失。
- **日志页新增 AI 日志**：底部「日志」页增加「终端日志 / AI 日志」切换，可直接查看当前会话的 AI 回显记录，也可点「打开日志目录」查看原始文件。
- **始终记录**：AI 回显日志不受会话「终端日志」开关影响；会话未开启终端日志时，AI 执行过什么、看到了什么仍然有记录。
- **脱敏与保留策略**：AI 回显日志沿用现有敏感信息脱敏规则，并按「日志存储 → 保留天数」统一清理。
- **回显到人工终端时同步落盘**：开启「AI 输出同时在人工终端回显」后，回显内容也会写入该会话的终端日志，避免两处记录不一致。

## V1.0.0.8（2026-11-23）

### 改进

- **AI 只读标签支持复制**：选中文本后按 `Ctrl+C` 或 `Ctrl+Shift+C` 即可复制到系统剪贴板，状态栏显示「已复制」；没有选区时不拦截按键。此前标签只能查看，复制快捷键没有响应。

## V1.0.0.7（2026-11-22）

### 安全

- **内置只读白名单收紧**：移除 `ip`、`ifconfig`、`mount`、`date`、`hostname` 等带写子命令的裸命令，改为 `ip addr show`、`ip route show`、`ip link show`、`ip neigh show`、`timedatectl status` 等只读子命令；`top -b` 改为 `top -b -n 1`，避免无限刷新。
- **补齐常用只读命令**：新增 `ls`、`stat`、`wc`、`readlink`、`lsmem`、`pgrep`、`pidof`、`pstree`、`swapon --show`、`blkid`、`docker images`、`docker logs --tail`、`docker version`、`docker info`、`kubectl get pods|nodes|svc|deploy|events`、`kubectl describe pod|node|deploy|svc`、`kubectl logs --tail`、`kubectl top` 等条目。`ls -la /tmp` 这类常见只读命令不再被误拦。
- **新增路径边界校验**：命令中的绝对路径必须落在白名单已声明的文件或目录内；`cat /etc/os-release /etc/shadow` 这类顺带读取会被拒绝。`..` 路径穿越、`$` 与 `~` 展开一律拒绝，防止白名单前缀被用来读目录外的文件。
- **新增危险参数拦截**：即便命令名在白名单内，`tail -f`、`journalctl --vacuum-*`、`crontab -r`、`curl -X`、`ss -K`、`dmesg -C` 等参数也会被拒绝，避免只读命令被参数变成写操作或无限跟随。
- **root 登录会话限制**：会话以 `root` 登录时，只读诊断只放行内置只读条目；自定义条目返回 `DIAG_COMMAND_DENIED`，并提示改用可写接入逐条审批。

### 说明

- 白名单保存在配置中，升级后已有配置不会自动替换为新的内置清单；需要在「设置 → AI安全 → 只读诊断命令白名单」中按新清单调整一次。
- 拒绝响应新增 `root_login` 字段与更明确的中文 `detail`；`session_attach` 的 `diag_allowlist` 在 root 登录会话中返回实际生效的内置条目。

## V1.0.0.6（2026-11-22）

### 修复

- **AI 选项卡拖动底部调节栏不缩放**：AI 面板此前缺少普通终端的完整 flex 高度约束，终端会按内容撑高并溢到底部面板后面。现在 AI 面板与普通终端一样受工作区高度约束，底部面板增大时终端同步缩小，不再遮挡内容。
- **持续拖动时重排被推迟**：原来的 120 毫秒尾部去抖会在连续拖动时不断取消重排。现在每个动画帧最多执行一次尺寸适配，拖动过程中即可更新终端行列与画布。
- **隐藏标签恢复后尺寸未刷新**：AI 标签重新显示时会在下一帧主动重算尺寸，避免保留隐藏前的旧行列数。
- **AI 终端字号偏好字段错误**：改为读取与普通终端一致的 `terminal_font_size`，设置页修改字号可正确同步到 AI 终端。

## V1.0.0.5（2026-11-22）

### 修复

- **申请原因乱码判定漏判**：原先只识别「全为问号」的文本，`????????? inode`、`???? 检查 nginx` 这类中文后拼接 ASCII 的情况会原样展示。现在后端与前端共用同一套规则：问号累计 ≥ 4 个、问号占比过半、或以问号开头后接空格/结尾都视为编码异常；单个问号（如 `检查 nginx 状态?`）仍原样保留。判定为异常时审计日志只记录 `reason_length` 与 `encoding_suspect=true`，不写原文。
- **`session_detach` 返回的 `mode` 错误**：此前按「writer / 非 writer」二元推断，diag 接入会被返回成 `read`。现在从 `attach_token` 对应的接入记录读取真实模式，固定返回 `{"ok": true, "mode": "write|read|diag", "note": ...}`，文案分别为「写入接入已释放」「只读诊断观察者已释放」「只读观察者已释放」；detach 审计事件同时写入真实 `mode` 与 `connection_id`。

### 改进

- MCP HTTP 的所有 JSON 响应统一带 `Content-Type: application/json; charset=utf-8`，错误体同样适用，避免非严格 UTF-8 客户端二次解码成乱码。

### 文档

- `SKILL.md` 与 `AI-使用说明.md` 补充乱码判定规则与 `session_detach` 新增返回结构。

## V1.0.0.4（2026-11-22）

### 修复

- **申请原因乱码**：客户端把中文 `reason` 编码成问号时，审批弹窗与 AI 活动不再显示 `????????`。后端在创建审批单时识别全为问号的文本并替换为「未提供可读原因（客户端编码异常）」，前端同样兜底。
- **AI 只读终端适配底部面板拖动**：面板高度连续变化时改为 120 毫秒防抖后重新适配，终端画布不再溢出到面板下方。
- **AI 只读终端支持 Ctrl+滚轮缩放**：字号范围 10–24，缩放结果写入界面偏好；设置页修改字号也会同步到已打开的只读终端，不重建实例。

### 界面

- 用户可见文案改为中文：`diag` → 只读诊断、`Attach Token` → 接入令牌、`BLOCKED` → 已拦截、`exit 0` → 退出码 0、`ai finished` → 正常结束、`stale` → 数据已过期、`platform/last_success_at/last_error` → 平台 / 最近成功采样 / 采样错误。
- 触发规则与原因统一走中文映射；AI 活动里的待审批卡片同样显示中文原因与规则。

### 文档

- `SKILL.md` 与 `AI-使用说明.md` 补充 `reason` 规范：简短中文，8–60 字，写清目的与范围；禁止问号占位、空字符串、`test`、`diag`、emoji 与 Markdown；客户端编码异常时改用简短英文。
- 设置页白名单说明改为实际的匹配规则：普通条目按完整命令或参数边界匹配，以 `/` 结尾的条目按目录前缀匹配。

## V1.0.0.3（2026-11-22）

### 修复

- diag / read 观察者此前在人工终端顶部没有提示，也没有踢出入口。现在只要 AI 处于接入状态，顶部就显示「AI 诊断观察中 / AI 只读观察中」及「✕」按钮；点击后调用强制 detach，可直接回收无法主动收尾的观察者。

## 1.0.0-2（2026-11-22）

### 新增

- **diag 只读接入模式**：`session_attach` 支持 `mode=diag`，非独占、可多观察者；只能执行白名单内的只读命令（`ss`、`df`、`journalctl`、`systemctl status` 等），不允许管道、重定向、命令串联和 root。
- **任务级授权**：`mode=write` 接入时可声明 `task`（目标 + 有效时长）。任务内白名单只读命令免逐条审批，写操作、高危命令和 root 仍需单独确认；任务到期自动 detach，并在 AI 只读标签写入「任务已结束」提示。
- **AI 标签任务状态**：状态栏显示当前任务目标与任务剩余时间。
- **设置项**：新增 diag 开关、只读命令白名单、任务授权最长时长（1–1440 分钟）。
- **白名单校验**：拒绝 `; | & > <`、反引号、`$(`、`${`、反斜杠和换行，避免白名单前缀被拼接成任意命令。

### 修复

- **sudo 错密返回码**：错误密码返回 `SUDO_AUTH_FAILED` 并计入连续失败次数；达到「密码错误锁定次数」（默认 3 次）后按「sudo 锁定时长」（默认 300 秒）锁定，不再表现为执行超时 `TIMEOUT`。
- **发布构建**：无法结束的僵尸进程不再中断 `npm run release`，改为告警后继续。

### 文档

- 统一 `使用手册.md`、`AI-使用说明.md`、`SKILL.md` 中关于 sudo 错密行为的说明，删除已过期的「错密返回 TIMEOUT、锁定不触发」已知问题。
- 新增升级注意事项：更新 Chena-Shell 后，需要在 AI 客户端重连 MCP 服务以刷新 `tools/list`，否则可能因客户端缓存旧 schema 而出现「文档有、调用报错」。

### 升级注意

- 更新后请完全退出旧实例，并在 AI 客户端重连 MCP 服务。
- 旧版本签发的 attach token 不会跨版本延续，需要重新 attach。

## 1.0.0-1（2026-11-22）

### 新增

- **AI 独立只读标签**：AI 执行回显进入独立「AI 只读」标签，不再混在人工终端中；人类可查看、选中复制，但不能输入或粘贴。
- **独立输出通道**：新增 `ai_replay` 与 `ai-terminal-data`，AI 标签晚挂载可补齐历史。
- **附着状态可视化**：标签与状态栏显示 `connection_id`、主 Shell / 复制渠道、模式、剩余时间与 sudo 配额。
- **双显开关**：设置中可选择 AI 输出是否同时在人工终端回显，默认关闭。
- **多连接定向 attach**：复制 SSH 渠道后可用 `connection_id` 绑定具体终端，`session_read` 始终读取同一连接。

### 修复

- **审批单消耗**：attach 前置校验失败（如已有 writer 接入）不再消耗人工审批单，重试无需重新批准。
- **关闭旧标签后 AI 输出丢失**：AI 回显不再依赖人工终端标签存活。

### 升级注意

- AI 输出默认只进入 AI 只读标签；如希望人工终端也可见，请在设置中开启双显。
